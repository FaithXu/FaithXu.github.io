# 创建 AI 网关

**预期阅读与操作用时**：5 分钟

## 概述

AI 网关是您访问各类大语言模型（LLM）的统一入口。创建 AI 网关后，您将获得一个 API 密钥，用于后续所有 API 调用。

本指南将引导您完成 AI 网关的创建，并重点介绍如何配置 Token 配额以控制用量和预算。

---

## 操作步骤

### 步骤一：登录并进入 AI 网关

1. 登录 [zenConsole](https://console.zenlayer.com)（使用您的 Zenlayer 账号）
2. 在顶部菜单栏中，依次进入 **产品 > AI 网关**
3. 点击 **创建 AI 网关**

---

### 步骤二：配置 Token 配额

Token 是模型处理文本的基本单位。Token 配额定义了该 API 密钥可使用的最大 Token 总数，包括输入 Token、输出 Token、缓存 Token，以及请求处理过程中消耗的任何其他 Token。

**默认情况下，配额为“无限配额”**——这意味着 API 密钥可以无限制地消耗 Token。

#### 什么时候该设置配额？

| 场景             | 建议                              | 原因                               |
| :------------- | :------------------------------ | :------------------------------- |
| **✅ 生产环境**     | **强烈建议设置配额**                    | 防止突发流量或异常代码导致预算超支。配额是最后的“预算安全阀”。 |
| **⚠️ 开发/测试环境** | 可选。建议设置**较低配额**（如 10,000 Token） | 即使代码出现死循环或配置错误，损失也控制在极小范围内。      |
| **❌ 不设配额**     | 你希望该 API 密钥“永远在线”，且完全不担心用量失控    | 例如内部演示环境，或已有其他层级的流量控制。           |

> 💡 **建议**：如果你不确定业务用量，可以从一个较低的配额（如 100,000 Token）开始，运行 1-2 天后观察实际消耗，再根据情况调整到合适的数值。

#### 如何设置

1. 默认情况下，**无限配额**处于勾选状态
2. 如果你希望限制该 API 密钥可消耗的最大 Token 数量，请**取消勾选“无限配额”**
3. 在出现的输入框中，输入你期望的配额数值（单位：Token）

**示例**：如果你将 Token 配额设置为 `1,000,000` Tokens：

- 该 API 密钥总共最多可消耗 1,000,000 个 Token
- 一旦达到配额上限，该 API 密钥将被**自动暂停**
- 在更新配额之前，将不允许继续消耗 Token 或发起 API 请求

---

### 步骤三：（可选）配置 API 密钥过期时间

你可以为临时访问或项目型访问设置一个过期时间。

**可选值**：
- 7 天
- 30 天
- 60 天
- 90 天
- 长期有效
- 自定义

> 💡 **提示**：留空表示永久有效。如果同时设置配额和过期时间，**先达到的条件生效**。

---

### 步骤四：设置 AI 网关名称

为你的 AI 网关实例设置一个标识名称。

**建议格式**：`项目名-环境-用途`

**示例**：`recommendation-api-prod`

---

### 步骤五：更多设置（可选）

你可以将 AI 网关实例加入到指定的资源组中。在资源组内，可以为特定成员授予资源的相应权限。

> 📖 更多信息请参见[创建资源组 | 中文 | Zenlayer Docs] (https://docs.console.zenlayer.com/welcome/cn/platform/team-management/create-a-resource-group)。

---

### 步骤六：完成创建

1. **确认并同意** AI 网关相关条款
2. **⚠️ 重要提示**：创建成功后，页面将仅显示一次 API 密钥。请**准备好保存位置**（如密码管理器或安全笔记），关闭页面后将无法再次查看。
3. 点击 **创建** 以创建 AI 网关

---

## 结果

创建成功。你现在拥有一个 **API 密钥**，可用于后续所有 API 调用。

你可以查看 [API 文档](https://docs.console.zenlayer.com/api-reference/cn/compute/aig)了解如何使用该密钥调用接口。

---

## 验证配额是否生效

创建完成后，进入 AI 网关详情页，查看“Token 配额”字段，确认显示的值与你设置的一致。

---

## 下一步操作

创建完成后，你可以：

- **查看详情**：点击 AI 网关名称，进入详情页面以查看日志、数据分析和基础信息
- **管理 Token 配额**：取消勾选“无限配额”以输入新的配额上限
- **管理过期时间**：选择所需的 API 密钥过期时长
- **复制 AI 网关**：点击“复制 AI 网关”，即可创建一个配置相同的 AI 网关
- **删除**：如果你不再需要该 AI 网关，点击“删除”即可删除

## 常见问题（FAQ）

### Q1：设置 Token 配额后，如果用量超过了，会不会产生额外费用？有没有缓冲期？

**答：不会产生额外费用，也没有缓冲期。**

Token 配额是**硬限制**。一旦用量达到你设置的上限，该 API 密钥会被系统**立即自动暂停**。后续所有 API 请求都会返回 `403 Forbidden` 错误码 `QUOTA_EXCEEDED`，直到你手动提高配额为止。

系统不会允许任何超量消耗，因此**绝无意外账单**。

> ⚠️ **边界情况说明**：如果一个 API 请求正好在配额用尽时发起，系统会尝试完成该次请求。该次请求的 Token 会正常计入配额（可能导致略微超出上限），但请求成功后密钥会立即被锁定。不会出现“请求执行一半”的情况。

---

### Q2：Token 配额是累计总量，还是每月/每周自动重置？

**答：当前版本为累计总量（Lifetime Total），不会自动重置。**

配额是从 API 密钥创建开始，所有成功消耗的 Token（包括输入、输出、缓存等）的**总和**。配额用尽后，密钥永久暂停，直到你手动提高配额数值。

**它不会在每月 1 号或任何周期自动清零。**

---

### Q3：**我设置的 100 万 Token 配额，大概要花多少钱？**

**答：取决于你使用的模型，以及输入和输出的 Token 比例。**

#### 1. 关键澄清：配额 ≠ 费用

- **Token 配额**是 Zenlayer AI 网关的**用量控制功能**，而非计费单元。设置配额本身**不会直接产生费用**。
- 你的实际费用由**背后模型提供商**（如 OpenAI、Anthropic、Meta 等）的官方定价决定。
- **Zenlayer 不额外收取 Token 费用。**

#### 2. 计费规则

模型计费同时包含两种 Token：

| 类型 | 说明 | 价格趋势 |
| :--- | :--- | :--- |
| **Input Tokens** | 你发送给模型的内容（问题、提示词、历史对话等） | 相对便宜 |
| **Output Tokens** | 模型返回给你的回答 | 通常比 Input 贵（如贵 8 倍） |

**配额统计的是 Input + Output + 缓存等所有 Token 类型的总和。**

#### 3. 如何查询具体价格

1. 登录 zenConsole
2. 进入 **产品 > AI 网关 > 模型目录**
3. 查看不同模型（如 `gpt-5.4`、`claude-opus-4-7`）的定价

控制台以 **每百万 Token（MTok）** 为单位显示，例如：
- Input：`$1.250 / MTok`
- Output：`$10.000 / MTok`

#### 4. 费用计算公式

```
总费用 = (Input Token数 × Input单价) + (Output Token数 × Output单价)
```

**示例**：以控制台中某模型的价格为例
- Input：$1.25 / MTok
- Output：$10.00 / MTok

假设你的 100 万 Token 配额中，Input 占 70 万，Output 占 30 万：
- Input 费用：0.7 × $1.25 = **$0.875**
- Output 费用：0.3 × $10.00 = **$3.00**
- **预估总费用：$3.875**

> 💡 **提示**：实际费用取决于你的使用模式（Input 和 Output 的比例）。建议先用小配额（如 10,000 Token）测试，观察实际消耗和账单后再调整。

---

### Q4：我同时设置了 Token 配额和过期时间，哪个先生效？

**答：先达到的条件先生效。**

| 情况 | 生效条件 | 结果 |
| :--- | :--- | :--- |
| **配额先耗尽** | Token 用量达到设定上限 | API 密钥**立即暂停**，即使过期时间未到也无法使用 |
| **过期时间先到** | 到达设定的过期日期（如 30 天后） | API 密钥**自动失效**，即使还有剩余配额也无法使用 |

**实际应用场景**：

你可以利用此机制创建“项目制”API 密钥。例如：为一个为期 7 天的活动创建密钥，设置：
- 过期时间：7 天
- Token 配额：10 万

无论是活动结束（时间到期）还是预算用尽（配额耗尽），该密钥都会停止使用，完美匹配项目生命周期。

>✅ **最佳实践**：对于生产环境的关键应用，建议**不设过期时间**，只依赖配额进行管理，并定期查看用量，避免因时间到期导致服务意外中断。

## 最佳实践建议

| 实践                   | 原因                            |
| :------------------- | :---------------------------- |
| **为不同环境使用不同 API 密钥** | 开发、测试、生产环境分开管理，互不影响           |
| **定期审查配额使用率**        | 发现异常增长趋势，提前优化或扩容              |
| **将配额信息纳入监控仪表盘**     | 被动等通知不如主动看趋势                  |
